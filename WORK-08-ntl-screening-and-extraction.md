# NTL: screen imported notes, move state out of the settings table, decide core vs. optional

The Note Transport Layer is integrated as a core client concern when it's architecturally an optional transport: it occupies a field on `Client`, is auto-enabled by the `testnet()`/`devnet()` builder presets, extends `sync_state` and `SyncSummary`, and adds cursor methods to the `Store` trait. Its persistent state lives as three opaque blobs in the settings KV table — the fetch cursor, the relay outbox (full undelivered note payloads, rewritten wholesale, silently reset to empty on parse failure), and the covered-tags set — with no schema, no migration story, and no atomicity with the note records they correspond to. Most urgently, notes fetched from the transport are imported with **no screening whatsoever**: `fetch_transport_notes` wraps everything as `ExpectedNote` and imports it, even though tags are lossy prefixes by design, so any third party can bloat a client's store with irrelevant records under a matching tag — records the `NoteScreener` would reject if it were consulted, and the note details needed to consult it are fully available at import time.

## Motivation

- Unscreened import is a free spam vector: tags are lossy prefixes *by design*, so any third party can pollute any client's store with junk `Expected` records — reported in `SyncSummary.new_private_notes` as if meaningful — at zero cost to the attacker.
- The outbox blob can silently discard undelivered note payloads on a parse error, in a system where the payload **is** the money; state that can vanish on a deserialization hiccup must not live in a KV blob.
- NTL is enabled by the `testnet()`/`devnet()` presets without the user asking — extra network traffic, storage, and attack surface by default, for a feature many clients never use.
- Plaintext transport of private note details undermines the core promise of a privacy rollup; every primitive for sealing already ships, so the gap is integration, not research.

## Plan

- **Screening (do first, independent of everything else):** run transport-fetched notes through the `NoteScreener` before import; drop (or import-as-flagged, behind an option) notes with no relevance to tracked accounts. Surface counts so callers can observe filtering. Small standalone PR; should land before the release regardless of the architectural decision.
- **First-class storage:** replace the three settings blobs with real tables — a per-note-row outbox instead of a rewrite-the-world blob (undelivered payloads must never be droppable by a parse error; today `load_relay_outbox` logs "dropping unreadable relay outbox" and discards); cursor and covered tags as proper columns. Rides WORK-02's pre-freeze migration.
- **Opt-in, not opt-out:** the `testnet()`/`devnet()` presets should not silently enable NTL; make it an explicit builder step.
- **E2EE and attachment integrity (from the review artifact's `priv-1`/`priv-2` — merge into this line):** transport payloads are plaintext end-to-end today; every needed primitive already ships (miden-crypto sealed boxes, `Address` already carries an optional `SealingKey`, the transport proto's details field is already opaque bytes) — the missing piece is recipient key management in the `Keystore` trait. The review also flagged an attachment bug; **verified against `next` 2026-07-23, partially fixed since the review**: the transport wire format still doesn't carry `NoteAttachments` (`rejoin_note` rebuilds with empty attachments and documents it), but the ID-corruption half was mitigated by PR #2295 — import now keys off the header's ID (`note_transport/mod.rs:460`). Remaining defect: attachments are silently dropped on transport delivery, so the stored note record loses them. The E2EE envelope should seal `(NoteDetails, NoteAttachments)` together, closing the gap for good.
- **Core vs. optional (decide with WORK-03's crate-split design):** the `NoteTransportClient` trait boundary already exists and `Client` already holds it as an `Option` — the invasive parts are the sync-path coupling (`sync_state` → `sync_note_transport`, `SyncSummary.new_private_notes`) and the Store-trait cursor methods. Extraction shape: core keeps the trait plus a sync extension hook (precedent: `NoteObserver`/`OnNoteReceived`), and the NTL implementation moves to its own crate owning its own storage. Full removal is the maximal version of the same move; trait-plus-hook keeps it available without making every client carry it.
